## 실행 결과

- `npm run typecheck`, `npm test`: 14개 테스트 파일 통과. `npm run build` 성공; 메인 청크 500kB 경고 유지.
- Linux Rust 기본 47 통과/1 ignored, simulation 48 통과/1 ignored, 양쪽 Tauri 권한 통합 각 1 통과. 루프백 접근을 위해 샌드박스 밖에서 실행했다.
- 실제 Tauri/WebKitGTK 개발 simulation 빌드, 격리 XDG 프로필 및 WebDriver: 최초 안내와 건너뛰기·새로고침 후 유지, 메뉴 9개, Dark/Day 전환, 패널·메뉴, 3개 집중 보기, 네이티브 전체 화면 진입/종료 요청, 지도 검색, 임무 작성/복제, 시뮬레이션 수신·안전 경고, 기록/재생, 오프라인 키 입력과 전체 화면·패널 전환 시 입력 초기화가 통과했다. 창 관리자 없는 Xvfb 환경이며 키 입력은 합성 DOM 이벤트다. 전체 화면 요청 성공은 Windows/일반 데스크톱 창 관리자에서의 시각적 동작을 보증하지 않는다.
- Linux Xvfb 2560×1440 화면에서 창 크기 910×512, 1366×768, 1440×900, 1920×1080, 2560×1440 각각의 Dark/Day와 9개 메뉴를 열어 안전 배너·명령 잠금이 뷰포트 안에 있고 상태줄에 가로 넘침이 없음을 자동 검사했다. 시스템 설정을 제외한 화면을 캡처했다. 이것은 모든 글자·팝업·내부 스크롤의 시각 검증이 아니다. 910×512 직접 캡처에서 지도 공간 부족과 여러 내부 스크롤을 확인해 미해결로 남긴다. 910×512는 1366×768/150%의 대략적 논리 크기를 모사한 것일 뿐 실제 Windows 배율 시험이 아니다.
- 중간 검사 1회는 새로고침 이전 DOM을 읽어 첫 실행 재진입 검사가 실패했고 WebDriver refresh 대기 후 통과했다. 다른 1회는 전체 화면 종료 시 요소 재생성 중 WebDriver 클릭 404가 발생했고 전환 대기 후 같은 시나리오가 통과했다. 해당 실패 JSON도 증거 폴더에 보관했다.
