# Phase 3 지도 구조 — 진행 기록

현재 MapView는 OpenLayers 인스턴스, VWorld 래스터·검색·건물 서비스, WGS84 임무 선택, 기체 telemetry 및 벡터 오버레이를 한 컴포넌트에 결합한다. 임무 저장 데이터와 기록 형식은 유지한다. 별도 엔진의 실제 실험과 공통 기능 범위가 확인되기 전 불필요한 어댑터를 추가하지 않았다. 추후 경계는 WGS84 좌표, 기체 식별 및 최신성, 궤적, 현장 지오메트리와 카메라 상태를 입력으로 하고 렌더러는 지도 이동 이벤트만 반환해야 한다. 지도 조작은 비행 명령을 보내지 않는다.

2026-11-26 격리된 실험은 별도 package.json/잠금 파일과 Vite 진입점을 사용한다. 생산 frontend 의존성이나 Tauri 명령은 바꾸지 않는다. 실험 오류는 기본 지도에 전파되지 않는다. 양 엔진 사이 상태 이관 어댑터는 아직 구현하지 않았다.

## 개발 전용 Tauri 연결

`import.meta.env.DEV` 조건의 동적 import로 MapLibre 컴포넌트를 열고, 기존 OpenLayers 인스턴스는 유지한다. Global 종료·렌더링 예외 시 기존 지도로 돌아가며 지도 인스턴스와 ResizeObserver를 해제한다. 기존 선택 현장의 WGS84 중심·GeoJSON 외곽선·반경과 현재 세션의 최신 GPS만 읽는다. 임무 및 기록 데이터 형식은 변경하지 않는다. 반경은 기존 `incidentArea`의 EPSG:3857 결과를 GeoJSON WGS84로 되돌린다. 동일 시스템/컴포넌트, 시각 차이 및 좌표 범위를 확인한 실제 또는 합성 GPS만 기체 마커로 그린다. 두 엔진 사이의 지도 카메라·이동 궤적·방향에 대한 완전한 공통 상태 계층은 아직 없다.

외부 스타일·타일·glyph/sprite 및 worker 접근은 Tauri `devCsp`에서만 허용하고 기존 생산 CSP를 유지한다. 생산 Vite 빌드에서 실험 코드와 OpenFreeMap URL이 출력되지 않는 것을 확인했다. 이 격리는 새 지도 엔진을 생산에 채택한 의미가 아니다.
