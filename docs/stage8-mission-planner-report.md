## 구조와 저장 방식

React 임무 계획 화면은 기존 `MapView`를 재사용한다. 종합 관제의 검색 위치나 건물 선택을 임무 생성으로 전달하며, 임무를 열 때 저장된 WGS84 좌표·실제 제공 건물 윤곽과 반경을 지도에 복원한다. 기존 기본/위성 전환 및 건물 조회를 사용한다. 50m·100m 및 1~2000m 범위는 현장 조회 범위이며 비행 안전거리나 허용구역이 아니다.

단일 사용자·소량의 임무에 별도 서비스나 신규 패키지가 필요 없는 JSON을 선택했다. SQLite는 큰 목록의 검색·동시 접근·복잡한 관계 처리에 유리하지만 현재 요구에 비해 의존성과 마이그레이션 복잡성이 크다. Rust가 Tauri의 사용자 데이터 디렉터리 `missions.json`을 사용하며 API 키 설정 파일과 분리한다. 실제 데이터는 저장소에 포함하지 않는다.

데이터는 버전 1, revision 및 임무 배열로 구성된다. 각 임무는 UUID, 이름, 생성·수정 시각, 유형, 상태, 건물 식별자·이름·주소, 경위도, GeoJSON Polygon/MultiPolygon 윤곽, 조회 반경, 목적, 담당자 및 메모를 가진다. 상태는 DRAFT/SAVED/ARCHIVED이고 유형은 화재 현장 탐색·건물 외부 정찰·주변 환경 조사·피해 현황 확인·사용자 지정이다. DRAFT 저장에는 이름이, SAVED/ARCHIVED에는 이름과 좌표가 필요하다. 범위·좌표·윤곽 형식, 개수·크기와 상태를 Rust에서 재검증한다. 스키마 버전은 향후 3D·경로·기록을 위한 마이그레이션 기준이며 해당 기능은 구현하지 않았다.

쓰기 전 기존 파일을 검증하고 revision을 확인한다. 임시 파일에 쓴 뒤 동기화하고 같은 디렉터리에서 교체해 중간 쓰기로 기존 파일이 훼손될 가능성을 줄인다. Unix에서는 파일 잠금으로 동시 쓰기를 차단한다. 데이터 손상·알 수 없는 스키마·읽기 오류가 있으면 원본을 보존하고 저장을 막는다. 파일을 백업한 뒤 올바른 백업을 복구하고 화면을 다시 열어야 한다. 자동 복구나 백업 생성은 구현하지 않았다. Windows에서 여러 프로세스의 동시 쓰기 잠금은 미구현이다.

## 구현 결과

임무 계획 메뉴에 새 임무, 목록·이름/주소/담당자 검색, 상세·수정, 복제, 보관, 삭제 확인, 기존 임무 불러오기, DRAFT 및 SAVED 저장을 추가했다. 저장하지 않은 편집 중 페이지를 벗어나거나 창을 닫을 때 확인을 요청한다. 선택 건물과 위치, 반경 변경을 임무 필드에 반영한다. 조회 범위는 관제 목적으로만 표시한다. 저장 상태는 비행 준비나 임무 실행 상태가 아니다. 임무 업로드, 기체 파라미터 변경, ARM 또는 다른 비행 명령은 추가하지 않았다.

주요 변경 파일: `frontend/src/Missions.tsx`, `frontend/src/MapView.tsx`, `frontend/src/App.tsx`, `frontend/src/index.css`, `src-tauri/src/missions.rs`, `src-tauri/src/main.rs`, `src-tauri/build.rs`, `src-tauri/capabilities/main.json`, `frontend/tests/missions.test.mjs`. 새 Tauri 명령은 기존과 같이 main WebView에만 허용된다.

## 검증 결과

- 프론트엔드 테스트 4개 파일 통과: 기존 오프라인 UI·지도 거리·3D 모의 테스트와 임무 생성/선택 값 변환. 임무 화면 전체 클릭 흐름을 자동 GUI 테스트한 것은 아니다.
- Rust 단위 테스트 25개 및 capability 구성 테스트 1개 통과. 임무 저장 후 다시 읽기, 수정·복제·보관·삭제, revision 충돌, 손상 파일 보존, 위치·반경·윤곽 오류 및 Unix 동시 쓰기 거부를 테스트했다. 테스트의 재읽기는 실제 앱 재시작 GUI 시험이 아니다.
- TypeScript 검사 및 Vite 빌드 통과. Vite의 500kB 청크 경고가 남는다.
- `cargo tauri build --bundles deb -- --offline` 통과. Ubuntu DEB 5,478,140 bytes(5.22 MiB), Stage 7.3의 5,430,784 bytes(5.18 MiB)보다 47,356 bytes 증가. DEB 파일 목록에서 Gazebo·PX4 SITL·텔레메트리 생성기를 찾지 못했다. 3D 실험 feature와 시뮬레이션 feature는 기본 빌드에서 켜지지 않는다.
- 릴리스 바이너리 및 DEB에서 로컬 API 키 문자열이 발견되지 않았다. 기존 로컬 임무 데이터를 작업 중 생성하거나 커밋하지 않았다.

## 사용자 GUI 확인 및 제한

원격 SSH 환경에서 GUI를 조작하지 않았다. 실제 VWorld 타일, 주소 검색 결과·건물 선택·윤곽 복원·반경 변경, 임무 생성·수정·삭제 확인, 앱 재시작 후 복구, 두 테마 및 창 크기, 지도 장애 중 안전 경고와 텔레메트리의 독립성을 일반 Ubuntu 그래픽 세션에서 확인해야 한다. 저장 충돌 또는 손상 오류가 표시되면 원본을 보존하고 원인을 확인한 후 임무 계획 화면을 다시 열어야 한다. 실제 드론 및 실제 임무 실행은 검증 범위가 아니다. 3D 렌더링과 권한 경계 역시 이전 단계의 PENDING 상태다.

실행 방법:

```sh
cd /home/jiwon/autonomous-uav-system
./src-tauri/target/release/firescene-gcs
```

종합 관제에서 주소 또는 건물을 선택한 뒤 임무 계획에서 새 임무를 만들고 저장한다. 종료·재실행 후 임무 목록에서 불러와 위치·윤곽과 범위를 확인한다. 복제·보관 및 삭제 취소/확인을 시험하고, 중요한 실제 데이터 대신 시험용 임무를 사용한다. 지도 및 안전 경고가 화면에서 가려지지 않는지도 확인한다.
