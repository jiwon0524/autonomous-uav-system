## 기술과 자료

2D는 OpenLayers와 VWorld WMTS 1.0.0을 사용한다. 별도의 원격 JavaScript를 관제 웹뷰에서 실행하지 않는다. 지도·위성 타일, 검색·건물 레이어와 원시 GPS 표시가 별도 계층이다. 검색 API 2.0과 데이터 API 2.0은 브라우저 CORS 허용 헤더가 관찰되지 않아 고정 VWorld HTTPS 주소만 호출하는 Rust 명령으로 요청한다. 요청 제한, 제한된 응답 크기, 타임아웃과 URL을 포함하지 않는 오류 처리를 적용한다.

VWorld 공식 SDK는 제공자 3D 지도에 적합하나 외부 스크립트의 Tauri 명령 접근을 격리해야 한다. [VWorld의 공식 교육 예제](https://github.com/V-world/V-world_API_sample/blob/master/%EB%B8%8C%EC%9D%B4%EC%9B%94%EB%93%9C_%EA%B5%90%EC%9C%A1/2026%EB%85%84_%EB%B8%8C%EC%9D%B4%EC%9B%94%EB%93%9C_%EA%B5%90%EC%9C%A1/Readme.md)는 WebGL 3D API 3.0을 사용한다. MapLibre는 벡터 타일 렌더링 후보이나 VWorld 3D 연동을 확인하지 못했다. CesiumJS는 3D Tiles·지형·점군 후보이나 VWorld의 실제 3D 데이터 제공 형식과 이용 허가를 확인하지 못했다. WebKitGTK·WebView2의 3D 호환성과 GPU·메모리·응답 속도는 미측정이다. [Tauri 원격 콘텐츠 권한](https://tauri.app/security/capabilities/)의 Linux iframe 제한을 고려해 현재 3D SDK를 관제 웹뷰에 로드하지 않는다. VWorld 공식 개발 문서는 접근이 불안정했으며 캐시·도메인 등록의 상세 이용 조건은 미확인이다.

## 구현 상태

- 사용자 설정에서 키를 교체할 수 있다. Linux 앱 설정 디렉터리의 `vworld-api-key` 파일에 저장하며 파일 권한을 0600으로 설정한다. 키는 평문이고 지도 타일 요청 URL에 포함되므로 완전한 비밀 저장소가 아니다. 과거 웹뷰 로컬 저장소의 키는 설정 저장 시 파일로 옮긴다. 발급받은 키를 로컬 파일에 설정했다.
- 2D 기본·위성 지도 전환, 이동·축소·확대, 축척, 중심 좌표, 초기화, 크기 변경 대응, 제공자 표시, 키 미설정·타일 오류 안내를 구현했다. 레이어 전환 시 중심과 배율을 유지한다. 타일의 인증 오류와 네트워크 오류는 구분할 수 없다.
- 검색은 도로명·지번·장소, 결과 목록과 선택 이동을 구현했다. 1초 간격 제한과 요청 순서 확인으로 이전 결과가 최신 결과를 덮지 않도록 한다. 빈 결과와 인증 오류, 서버/통신 오류를 표시한다.
- 지도 클릭 시 VWorld `LT_C_SPBD` 도로명주소 건물 데이터를 조회하고 클릭 점이 실제 윤곽 내부인 결과만 선택한다. 응답에서 제공하는 건물명·주소·관리번호를 표시하고 윤곽을 강조한다. 높이·용도는 제공되지 않아 표시하지 않는다. 조회가 없는 지역은 미제공으로 표시한다.
- 선택 건물 윤곽의 투영 좌표 외접 사각형 중심을 사용해 50m·100m·사용자 지정 반경(1~2000m)을 그린다. OpenLayers의 구면 거리 원을 WGS84에서 생성하고 EPSG:3857로 표시한다. 반경은 조회 범위이며 안전거리나 허용구역이 아니다. 경계의 현장 측량 정밀도는 검증하지 않았다.
- Stage 5 GPS_RAW_INT 좌표가 LIVE이고 동일 송신자·거의 동일 시각일 때 원시 GPS 마커와 최대 500점 경로를 표시한다. 오래되거나 끊기면 마커와 경로를 제거하며 다시 수신해도 빈 구간을 잇지 않는다. 하드웨어 링크 또는 시뮬레이션 출처를 구분하되 송신자 인증은 없다. 추정 위치, 방향·고도 표시 및 마지막 위치 보존은 미구현이다. 초기 중심은 기체 위치가 아니다.
- 기존 통신·안전 감시·비행 명령 잠금을 변경하지 않았다. 3D, 2D/3D 전환, 실시간 점군, 임무 및 비행 명령은 구현하지 않았다. 3D 사전 지도는 화재 현장의 실시간 상태나 실내 상황을 의미하지 않는다.

## 검증 결과

제공된 키로 직접 HTTPS 요청 시 기본 타일은 PNG 200, 위성 타일은 JPEG 200을 반환했다. 검색 API의 장소 예제는 결과 3개를 반환했고 잘못된 시험 키는 `INVALID_KEY` 오류를 반환했다. 건물 데이터 API의 서울시청 부근 사각 조회는 건물 5개와 실제 속성을 반환했다. 이는 앱에서의 성공을 뜻하지 않는다. 구면 거리 계산에서 반경 50m·100m·1000m의 첫 꼭짓점을 OpenLayers 거리 함수로 확인했다.

Tauri 앱 창 실행은 확인했으나 화면 캡처가 검은 화면으로 반환되어 GUI에서 키 읽기, 타일 표시·전환, 검색, 건물 선택, 범위 표시와 리사이즈를 확인하지 못했다. Tauri `tauri://localhost` 및 Windows `http://tauri.localhost`의 도메인 인증, Windows WebView2, 인터넷 중단, 위치 갱신·오래됨, 시뮬레이션 출처 및 지도 장애 중 안전 감시의 GUI 회귀는 미검증이다. 실제 기체는 연결하지 않았다.

TypeScript 검사와 프론트엔드 빌드, Rust 기존 테스트 19개, Ubuntu Tauri 릴리스 DEB 빌드를 수행했다. 이전 DEB는 3.08 MiB, HTTPS 의존성 추가 후 5.18 MiB였다(후속 변경 시 재빌드 값 참조). CPU·GPU·메모리·기동 시간은 실측하지 못했다. 3D 엔진은 로드하지 않고 경로는 500점으로 제한하며 맵 종료 시 인스턴스와 관찰자를 해제한다. 실제 성능 최적화 효과는 미검증이다. DEB 파일 목록과 프론트엔드 및 릴리스 바이너리에서 테스트 생성기·Gazebo·PX4 SITL·시뮬레이션 연결 명령 문자열을 찾지 못했다. 이는 검사 범위 내 결과다.

## 2026-11-25: 3D SDK 조사 및 SSH 환경 재검증

상태: **3D 구현 미완료**. 이 절은 앞의 진행 보고에 추가된 최신 결과다. 2D 지도 및 기존 기체·안전 기능을 다시 구현하지 않았다.

[VWorld 공식 WebGL3 예제](https://github.com/V-world/V-world_API_sample/blob/master/%5BWebGL3%5D%20%ED%81%B4%EB%A6%AD%EB%90%9C%20%EB%AA%A8%EB%8D%B8%20%EC%88%A8%EA%B8%B0%EA%B8%B0.html)는 WebGL 3D API 3.0의 `vw.Map`, `vw.CameraPosition`, `vw.CoordZ`, `vw.Direction`으로 지도를 초기화하고 `ws3d.viewer` 및 Cesium 피처 선택을 사용한다. 기존 키로 초기화 스크립트 요청에 정상 응답과 유효 표시가 반환됐다. 이는 스크립트 요청의 결과일 뿐 3D 타일·지형 표시, 등록 도메인 일치 또는 Tauri 내부 실행의 증거는 아니다. 현재 엔진을 실제 앱에 설치하거나 로드하지 않았다.

실제 받은 초기화 스크립트는 `domain`이 비어 있을 때 문서의 `location.protocol`이 HTTPS가 아니면 후속 JavaScript와 타일 주소를 HTTP로 선택한다. Linux Tauri의 기본 `tauri://localhost` 출처에서 이 분기를 타는 것은 코드상 확인했지만 실제 WebKitGTK 요청은 GUI에서 미검증이다. HTTP 코드를 관제 웹뷰에 허용하거나 등록되지 않은 인증 도메인을 임의로 지정하지 않았다. 제공자에게 Tauri 커스텀 스킴·도메인 등록과 HTTPS 3D SDK 지원을 확인해야 한다. Windows의 별도 WebView 출처도 검증이 필요하다.

[Tauri capability 문서](https://v2.tauri.app/security/capabilities/)는 외부 콘텐츠에 대한 명시적 권한 부여와 Linux iframe 구분 한계를 설명한다. 현재 별도 3D WebView, 그에 대한 capability 및 IPC 경계는 **구현·검증하지 않았다**. 특히 Tauri는 별도 앱 명령 권한 선언을 하지 않은 사용자 정의 명령에 기본 접근을 허용할 수 있으므로, 추후 `AppManifest::commands`와 main WebView 전용 capability를 적용하고 실제 거부 테스트를 마친 뒤 원격 코드를 실행해야 한다. 전체 CSP를 해제하거나 3D SDK를 메인 관제 WebView에 삽입하지 않았다. 실제 건물·지형, 방향별 시점, 2D/3D 전환, 선택 정보와 위치 공유는 모두 PENDING이다.

실제 API 재점검용 `python3 scripts/check_vworld.py`를 추가했다. 로컬 설정에서 키를 읽으며 키·요청 URL·예외 원문을 출력하지 않는다. 네트워크 접근이 허용된 환경에서 기본 PNG, 위성 JPEG, 장소 검색 3건, 건물 윤곽 5건 및 3D 초기화 응답을 확인했다. Tauri의 CSP, CORS, 도메인 인증이나 렌더링 성공을 대신 증명하지 않는다. VWorld 검색 응답에 CORS 허용 헤더가 없는 것은 이전 직접 요청에서 관찰했으며 앱의 검색·건물 요청은 Rust 경유다.

반경 함수에 유한 좌표 및 1~2000m 검증을 추가했다. 프론트엔드 자동 테스트에서 서울·부산 좌표의 50m, 100m, 2000m 원 전체 꼭짓점 거리를 확인하고 잘못된 입력을 거부했다. 기존 오프라인 UI 회귀 테스트가 OpenLayers CSS를 처리하도록 수정했다. `npm --prefix frontend test`, TypeScript 검사와 프론트엔드 빌드, Rust 테스트 19개를 통과했다. 실제 대상 장비의 메모리·CPU·GPU·기동 성능은 측정하지 않았다.

검은 화면은 이전 원격 그래픽 세션의 화면 캡처에서 관찰했을 뿐 원인을 특정할 증거가 없다. 캡처 경로·원격 세션, WebKitGTK·WebGL·GPU, 컨테이너 크기, CSP·CORS, VWorld 도메인 인증 및 실제 렌더링 각각 **PENDING**이며, 캡처 실패를 지도 실행 실패로 판정하지 않는다. 이번 SSH 작업에서는 시스템이나 원격 데스크톱 설정을 바꾸거나 GUI를 조작하지 않았다.

Ubuntu의 일반 그래픽 세션에서 사용자가 직접 확인할 실행 방법:

```sh
cd /home/jiwon/autonomous-uav-system
./src-tauri/target/release/firescene-gcs
```

시스템 설정의 키가 읽히는지 확인하고, 종합 관제에서 기본/위성 전환, 주소 검색, 건물 윤곽 선택과 50m·100m 범위, 창 크기 변경 및 인터넷 중단 시 안전 상태를 확인한다. 실제 기체 또는 개발용 시뮬레이션에서 GPS 마커·경로와 오래된 데이터 제거를 확인한다. 시뮬레이션은 개발 빌드에서만 확인한다. 3D 버튼과 지도는 아직 구현되지 않았으므로 검사할 수 없다. API 독립 진단은 같은 디렉터리에서 `python3 scripts/check_vworld.py`로 실행한다.

이번 리빌드 `cargo tauri build --bundles deb -- --offline` 성공, Ubuntu DEB 5.18 MiB로 이전 5.18 MiB와 표시 정밀도에서 동일하다. 프론트엔드 번들은 약 608 kB로 Vite의 500 kB 경고가 남는다. GUI와 3D 엔진 부하를 측정하지 않았으므로 성능 개선으로 판단하지 않는다.

## Stage 7.3: 별도 HTTPS 3D 페이지와 실험용 창

이 절이 앞선 3D 구현 상태를 대체한다. **3D는 실험 코드가 추가됐으나 실제 작동과 권한 격리 검증 전이며 기본 빌드에서 비활성이다.** 대상 건물·지형 렌더링을 성공했다고 판단하지 않는다.

### 구현 및 HTTPS

`frontend/public/vworld-3d.html`은 관제 UI와 별도 문서다. 공식 예제의 WebGL 3D API 3.0 초기화 스크립트를 그대로 HTTPS로 읽고 `vw.Map`, `vw.CameraPosition`, `vw.CoordZ`, `vw.Direction`으로 지도 시작을 요청한다. 공식 SDK의 `document.write` 방식에 맞춰 페이지 구문 분석 중 스크립트를 삽입한다. 지형·건물은 SDK가 제공하는 데이터에 맡기며 임의의 모델을 생성하지 않는다. 북·남·동·서·상단 및 초기화 버튼은 Cesium 카메라 호출을 준비하고, 마우스 회전과 확대·축소는 SDK에 맡긴다. SDK와 리소스 오류를 표시하되 시작 요청만으로 데이터 로딩 성공을 표시하지 않는다. 3D 미지원 지역 자동 판별은 미구현이다.

페이지는 실제 HTTPS 출처가 아니면 SDK를 호출하지 않는다. `domain` 값을 임의로 지정하거나 SDK 소스를 변경하지 않는다. 사용자가 VWorld에 등록하고 제공자가 허용한 HTTPS 도메인에서 이 페이지를 호스팅해야 한다. 공식 예제는 HTTPS 문서에서 SDK를 불러오는 방식을 보여주나, 이 키의 등록 도메인·별도 호스팅과 API 이용 조건은 확인되지 않았다. 페이지를 배포하지 않았고 실제 SDK 초기화, 제공자 도메인 인증, 3D 타일 및 지형은 PENDING이다. Tauri Linux의 `useHttpsScheme`에 의존하지 않는다.

실험용 `experimental-vworld-3d` Cargo feature와 빌드 시 `FIRESCENE_3D_PAGE_URL`을 모두 지정하면 별도 `map3d` WebView 창이 준비된다. URL은 쿼리·인증 정보 없는 HTTPS 주소여야 하며 같은 주소 이외로 탐색을 허용하지 않는다. 2D 선택 건물 중심 또는 지도 중심과 조회 반경을 URL fragment로 전달하므로 HTTP 요청 경로에 포함하지 않는다. 반경은 3D 페이지에서 수치로만 표시하고 윤곽·범위 원, 드론 위치·경로는 아직 3D에 표시하지 않는다. 방위 버튼은 건물의 실제 정면을 의미하지 않는다. 창을 열 때 2D 인스턴스를 해제하고 종료 이벤트 후 복원하도록 구현했으나 GUI 동작은 PENDING이다.

실험 창은 기존 로컬 키를 Rust에서 읽어 **명시적으로 설정한 HTTPS 페이지**의 세션 저장소로 전달한다. 따라서 해당 페이지와 그 페이지에서 실행하는 SDK는 키를 읽을 수 있다. 키는 HTML 파일·Git·페이지 URL에 들어가지 않지만 호스팅 서버의 콘텐츠를 신뢰해야 하고 클라이언트 키는 비밀로 보장할 수 없다. HTTPS 페이지가 등록 도메인이 아니거나 키가 없는 경우 기능을 사용할 수 없다.

### 권한 경계

모든 앱 명령을 `AppManifest::commands`에 등록하고 `main` WebView에만 열거형 capability를 부여했다. `map3d` 및 원격 출처에는 capability를 부여하지 않았다. 3D 페이지는 별도 창이며 원격 콘텐츠를 관제 WebView에 삽입하지 않는다. 와일드카드 capability는 없다. Rust 정적 구성 테스트는 핸들러 명령의 매니페스트 등록, main 전용 권한과 원격 권한 부재를 확인한다. **실제 Linux/Windows WebView에서 3D 콘텐츠가 IPC와 기체 통신을 호출하지 못하는지 확인한 것은 아니다.** 메인 창의 기존 명령과 안전 감시도 capability 변경 후 실제 GUI 회귀가 필요하다. 이 검증 전에는 일반 릴리스에서 3D를 켜지 않는다.

### 검증 및 남은 일

프론트엔드 자동 테스트는 별도 페이지에서 비 HTTPS 출처의 SDK 호출을 거부하고, 모의 SDK에 선택 좌표와 상단 시점을 전달하며 SDK 부재를 성공으로 보고하지 않는지 검사한다. 모의 테스트는 실제 VWorld 또는 WebGL 검증이 아니다. Rust 기본 빌드 및 실험 feature 검사를 수행했고, 권한 설정의 정적 검사와 기존 Rust 테스트를 수행했다. 실제 3D 창의 SDK·지형·건물, CORS/CSP, 권한 거부, 이벤트 수신·복원, 네트워크 장애 시 안전 감시 독립성, GPU·RAM 및 Windows는 PENDING이다. 3D 라이브러리나 공간정보 데이터는 앱에 추가로 번들하지 않았다.

A. 별도 WebView는 위 실험 구조로 준비했으나 격리 시험이 남았다. B. VWorld가 승인한 HTTPS 페이지가 필요하며 아직 호스팅하지 않았다. C. 다른 엔진의 VWorld 실제 3D 데이터 접근 권한과 형식은 확인되지 않아 사용하지 않는다. D. 같은 승인된 HTTPS 페이지를 일반 브라우저에서 시험하는 것은 임시 진단이며 관제 통합 검증이 아니다. Electron 전환은 하지 않았다.

일반 Ubuntu 그래픽 세션의 기본 빌드 실행:

```sh
cd /home/jiwon/autonomous-uav-system
./src-tauri/target/release/firescene-gcs
```

사용자는 먼저 2D 및 안전 감시의 기존 기능을 확인한다. 실험 3D는 기본적으로 비활성이다. 별도 보안 검증 환경에서 제공자 승인 도메인에 `frontend/public/vworld-3d.html`을 호스팅하고 API 등록·이용 조건을 확인한 경우에만 해당 HTTPS 페이지 URL로 `FIRESCENE_3D_PAGE_URL`을 설정하여 `cargo tauri dev --features experimental-vworld-3d`를 실행할 수 있다. 이 실험은 호스트에 로컬 키를 제공하므로 신뢰할 수 있는 페이지에서만 수행한다. 이 창에서 Tauri 연결·설정 명령 거부, 키·도메인 인증, 실제 3D 건물·지형, 시점 조작 및 닫기 후 2D 복원을 각각 확인해야 한다.

최종 검증: 프론트엔드 테스트 3개 파일 통과, 기본 Rust 단위 테스트 20개와 권한 구성 테스트 1개 통과, 실험 feature의 Rust 테스트 통과, 시뮬레이션 feature 컴파일 통과, TypeScript 및 프론트엔드 빌드와 Tauri Ubuntu DEB 빌드 통과. DEB는 5,430,784 bytes(5.18 MiB)로 이전과 표시 정밀도에서 같다. DEB 목록에서 Gazebo·PX4 SITL·테스트 생성기를 찾지 못했다. 프로덕션 Rust에는 시뮬레이션 핸들러가 feature 조건으로 제외되지만, capability 매니페스트에는 개발 빌드를 위한 권한 이름이 남아 있다. 변경 파일과 릴리스 산출물에서 로컬 키 문자열은 발견되지 않았다. Vite의 500 kB 청크 경고는 남아 있다.
