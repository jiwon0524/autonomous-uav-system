# Companion Computer 인터페이스 초안 v1

Stage 11은 상태 수신의 통합 기반이다. Pi·카메라 팀과 합의 전 초안이며 실제 장치나 프로덕션 보안은 검증하지 않았다. FC/PX4는 비행 제어와 독립 failsafe를 담당하고 Pi는 향후 인지·처리, GCS는 관제·표시를 담당한다. 이 채널에 비행 명령, 셸, 임의 실행, 임무 업로드 기능은 없다.

## 채널 선택

작은 상태 메시지는 GCS가 사용자가 입력한 숫자 IPv4/IPv6와 포트에 TCP 클라이언트로 접속하여 Pi가 보내는 UTF-8 JSON Lines를 읽는다. 프레이밍·순서·연결 손실 판별이 단순하고 별도 프레임워크나 수신 포트가 필요 없다. TCP는 혼잡 시 지연될 수 있다. UDP는 손실 허용 데이터에 적합하지만 순서·손실 감지가 필요하다. WebSocket은 브라우저 상호 운용성이 좋지만 이 단계의 상태 전용 연결에는 추가 프로토콜이 필요하다. HTTP는 상태 조회에 적합하지만 지속 스트림에는 반복 요청 또는 별도 스트리밍 설계가 필요하다. ROS2는 Pi 내부 컴포넌트에 유용할 수 있으나 발견·배포 복잡성 때문에 GCS 설치 의존성으로 삼지 않는다. 영상과 대용량 점군에는 별도 전송·압축·대역폭·지연 정책을 후속 선정한다.

## 상태 메시지

한 줄 최대 4096바이트(개행 제외), UTF-8 JSON 객체와 LF 개행. 첫 연결 및 이후 최소 5초 이내에 유효한 메시지가 필요하며 1초 주기를 권장한다. 필수 필드: `protocol_version` 정수 1, `device_id` 1–64 ASCII 영숫자/`-_.`, `timestamp_ms` UTC Unix 밀리초, `connection_state`는 `online` 또는 `degraded`. 장치 시계는 GCS 시계와 5분 이내로 동기화해야 한다. 수신 시각과 송신 시각은 구별하며 시간 오차만 검사하므로 재전송 공격을 막지는 못한다.

선택 필드는 생략 또는 null 가능하다. `cpu_usage_percent`, `memory_usage_percent`는 0–100, `cpu_temperature_c`는 -50–150. `ai_status`, `camera_status`, `mapping_status`, `sensor_status`는 `ready`, `running`, `degraded`, `error`, `offline` 중 하나다. `error_status`는 제어 문자 없는 UTF-8 문자열로 최대 256바이트다. 알 수 없는 필드, 형식·범위·버전 오류는 연결 오류로 거부한다. 호환되지 않는 확장은 새 버전 협의가 필요하다. 미수신 값은 미수신으로 표시한다.

```json
{"protocol_version":1,"device_id":"pi-01","timestamp_ms":1795560000000,"connection_state":"online","cpu_usage_percent":35.2,"memory_usage_percent":42.0,"cpu_temperature_c":52.1,"ai_status":"running","camera_status":"ready","mapping_status":"offline","sensor_status":"ready","error_status":null}
```

위 시간은 형식 예시이며 실행 시 현재 UTC 시각으로 바꾼다. 접속 3초 제한, 유효 메시지 5초 무수신 시 손실, 최초 접속 후 최대 3회 재시도(각 1초 간격). 오류가 나면 이전 메시지를 현재 값으로 표시하지 않는다. 연결 해제는 작업을 취소하고 상태를 초기화한다. 최대 한 개의 현재 스냅샷만 보유하며 메시지 큐를 유지하지 않는다.

## 신뢰 및 보안

TCP 상태 채널은 평문이고 암호화·인증·무결성·재생 방지가 없다. IP와 device ID는 인증이 아니다. 격리되고 신뢰 가능한 시험망 외에서는 사용하지 않는다. 운영 전 상호 인증 TLS, 자격 증명 수명주기, 권한 분리, 재생 방지, 네트워크 위협 모델과 장애 동작을 별도 설계·검증해야 한다. 호스트명 조회나 네트워크 탐색 없이 사용자가 지정한 주소에만 접속한다. GCS는 이 연결에 애플리케이션 데이터를 쓰지 않는다. 상태는 안전 감시·PX4 제어·비행 명령 권한과 연결되지 않는다.

## 카메라·3D 팀과 합의할 데이터 경계

아래는 구현된 전송 규격이 아니라 통합 계약에서 반드시 합의할 항목이다. 데이터에는 생산자 ID, 스키마 버전, 캡처 시각·시계 기준, 프레임 ID, 유효성 및 누락·오류 상태가 필요하다. RGB와 depth의 동기 오차·유실 및 해상도 변경을 명시한다.

| 데이터 | 합의할 메타데이터 |
|---|---|
| RGB | 인코딩·색 공간·폭·높이·프레임률·캡처 시각 |
| Depth | 형식·해상도·단위·유효 범위·무효값·RGB 정렬 및 동기 오차 |
| 카메라 내부 파라미터 | 해상도별 fx/fy/cx/cy, 왜곡 모델·계수, 보정 버전 |
| 카메라 위치·자세 | 기준 프레임과 대상 프레임, 방향, 단위, 회전 표현·순서, 불확실도 |
| Point cloud | 좌표 프레임·단위·타임스탬프·필드 형식·색상·크기 한도 및 분할 |
| 3D reconstruction | 모델 버전·프레임·스케일·갱신/완료 의미·파일 형식·크기 한도 |
| 객체 탐지 | 클래스·신뢰도 정의·화면 좌표/정규화 방식·프레임 ID·시각, 3D 위치가 있으면 좌표계·불확실도 |

좌표계의 축 방향, 오른손/왼손, 기준 원점, 지리 좌표의 datum, 고도 기준 및 변환 방향을 명시하고 FC NED, 카메라 optical 및 지도 좌표를 암묵적으로 혼용하지 않는다. 시계 동기·변환 정확도와 사생활·보존 정책도 후속 합의한다. 실제 영상·depth·점군 수신이나 SLAM·3D 렌더러는 아직 없다.

## 로컬 시험

개발 환경에서 `python3 tools/companion_status_fixture.py` 실행 후 GCS 시스템 설정에서 `127.0.0.1`, `8765`로 연결한다. 이 도구는 루프백만 열고 개발 소스에만 있으며 배포 DEB에 포함하지 않는다. 창에서 상태·연결 해제를 확인한다. 실제 Pi 및 GUI 시험은 별도다.
