# Stage 20-1: 기존 시스템 및 디자인 분석

기준: `dev/firescene-gcs` 632fe3f에서 분기한 `design-v2-experimental`. [최신 연구 자료](../references/research/firescene-design-v2-research.txt) 전체를 읽었다. 연구의 A(항공우주 관제)를 종합 관제의 정보 계층에 적용하고 C(목적지 중심 검색)는 기존 통합 검색을 보존한다. B(Globe)는 후속 검증 전 도입하지 않는다. Crew Dragon의 절제와 작업 중심 배치를 참고하며 실제 인증·조종 기능을 주장하지 않는다.

## 현재 구조와 문제

- `App.tsx`는 공통 헤더, 상태줄, 9개 내비게이션, 페이지, 기체 정보 패널을 구성한다. 종합 관제는 지도 아래 5개 값, 6개 그래프, 임무·이벤트와 조종 미리보기를 길게 쌓아 스크롤이 필요하다. 헤더와 패널에서 같은 상태가 반복되고 지도보다 부가 정보가 넓은 공간을 차지한다.
- `index.css`의 공통 토큰과 반응형 규칙은 Dark/Day 테마를 제공한다. 작은 데스크톱에서는 메뉴가 자동으로 아이콘만 표시되며 사용자가 접고 펼칠 수 없다. 최소 창은 850×620이다.
- `MapView.tsx`는 OpenLayers/VWorld 2D 타일과 검색, 건물 조회, 건물/반경·실제 GPS 경로를 표시한다. 검색 선택은 지도 이동이며 건물 선택과 다르다. 3D는 기본 비활성이다. 지도와 저장된 위치는 좌표/GeoJSON을 사용한다. 지도 엔진, 검색 API, 데이터 공급원은 구분해야 한다.
- `Missions.tsx`와 Rust `missions.rs`는 임무를 로컬에 저장한다. 선택된 임무와 지도 선택은 `workflow.ts`로 연결되며 저장 데이터 형식을 이번 단계에서 변경하지 않는다.
- `Telemetry.tsx`의 공유 외부 저장소는 수신값별 LIVE/STALE/INVALID 상태를 보존한다. `Safety.tsx`는 별도 안전 감시 및 경고를 표시한다. OFFLINE·UNKNOWN을 정상으로 바꾸지 않는다. `ManualPreview.tsx`는 비행 모드 최신성, 포커스와 타임아웃을 확인하며 별도 오프라인 입력 연습도 제공한다. 실제 비행 명령은 잠겨 있다.
- `Camera.tsx`와 `Spatial.tsx`는 팀원 데이터 수신·표시 인터페이스이며 lazy load된다. 처리 알고리즘이나 기존 계약은 수정하지 않는다. `RecordingStatus.tsx`와 `Recordings.tsx`는 기록 상태와 재생을 제공한다.

## 구현 계획 및 영향

1. 9개 메뉴와 더불어 접기/펼치기를 명시적으로 제공한다. 종합 관제는 중앙 지도, 하단 핵심 값과 조종 진입, 우측 현장/기체/안전/이벤트 상황 패널로 구성한다. 지도를 제거하거나 엔진을 바꾸지 않는다.
2. 그래프는 필요할 때 열고 조종 매뉴얼은 기존 ON 상태에만 나타나도록 유지한다. 모드 활성 중 패널이나 메뉴 변경 시 기존 입력 정리 로직을 보존한다.
3. 기존 데이터 소스와 무관한 숫자·기체를 만들지 않는다. 키보드 이벤트, 연결 안전 조건, MAVLink/Rust 명령 및 로컬 저장은 변경하지 않는다. 좁은 창에서는 내부 스크롤을 허용해 조작 접근성을 우선한다.
4. Dark는 연구의 배경 `#0B0F12`, 패널 `#151B1F`, 텍스트 `#E9EEF2`, 보조 `#8B99A3`, 선택 `#61B7FF`, 주의 `#FDB84B`, 위험 `#FF5A57`을 사용하고 Day도 별도 토큰을 유지한다. 시스템 글꼴을 우선하고 숫자는 tabular numerals를 쓴다.

## 검증 기준과 한계

기존 [전체 QA](full-qa-test-report.md)의 미검증 항목은 그대로 남는다. 사용자 확인으로 Ubuntu 실행과 위치 검색이 작동했으며 자동 QA는 제한된 메뉴/테마/검색, 시뮬레이션 수신과 기록을 확인했다. 실기체, 전체 키보드 이벤트, 장시간 성능, Windows 등은 미검증이다. 변경 전 실제 GUI 캡처는 `/tmp/firescene-qa-xvfb/00.png`에 있다(임시 파일). 이전 DEB는 5,713,738 bytes이며 이번 단계에서 새 패키지나 성능 수치를 만들지 않는다. 후속 단계에서 임무 UX, Tactical Map, 렌더러 분리, MapLibre와 Globe를 각각 검증한다.
