## 전송과 구현

여러 전송 후보의 지연·자원·WebView·보안 비교는 [카메라 및 Perception 인터페이스](camera-perception-interface-spec.md)에 기록했다. 초기는 MJPEG 계열의 JPEG 프레임을 별도 TCP 길이 프레이밍으로 받고 동일 패킷에 탐지 메타데이터를 넣는다. 이는 표준 MJPEG 서버와 직접 호환되는 규격이 아니다. 프레임과 탐지의 ID·시각이 일치하지 않으면 거부한다. JPEG를 JSON에 넣지 않고 별도 전송 엔진을 설치하지 않았다. 실제 운용 방식은 지연·대역폭 및 플랫폼 실측 후 결정한다.

카메라 관리자는 숫자 IP·포트로 나가는 연결, 접속·데이터 시간 제한, 마지막 프레임·수신 FPS·해상도·오류를 제공한다. 화면에서는 표시 FPS, 확대, 정규화 박스·클래스·신뢰도·트래킹 ID·제공된 거리, 탐지 켜기/끄기 및 객체 수를 표시한다. 원본 프레임과 SVG는 같은 비율의 영역을 사용한다. 화면을 떠나면 연결을 해제하고 객체 URL을 해제한다. 실제 GUI 정확성은 미검증이다. Depth는 원본 단위·무효값·내부 파라미터·컬러맵 경계만 정의했고 수신·시각화·거리 측정은 구현하지 않았다.

최대 헤더 16 KiB, JPEG 512 KiB, 1920×1080, 객체 50개, 초당 최대 10 프레임을 제한한다. 최대 한 개의 최신 프레임만 관리하며 오래된 데이터는 표시하지 않도록 한다. JPEG의 SOF 차원과 끝 마커를 확인하지만 전체 유효성은 WebView 디코더가 판정한다. 시계 오차 5초 이내를 요구하며 영상 지연은 UNKNOWN이다. FC·안전 감시 및 기존 Companion 상태 관리자는 별도이며 카메라 데이터가 비행 명령으로 연결되지 않는다. 반복 연결·악성 이미지·장시간 부하의 자원 사용량은 실측하지 않았다.

## 보안

영상과 Stage 11 상태 채널은 평문·미인증이므로 신뢰 가능한 격리 시험망에서만 사용한다. ID와 시각은 인증 또는 재생 방지가 아니다. 운영 전 상호 인증·암호화·자격 증명·부하 보호와 WebView/JPEG 디코더 위험을 검토해야 한다. CSP는 수신 JPEG를 표시하기 위해 `blob:` 이미지만 추가 허용한다. 임의 URL 입력, 셸, 임의 파일 읽기 및 비행 명령 기능은 추가하지 않았다. 카메라 화면은 지연 로딩된다.

## 자동 검증 및 산출물

- 프론트엔드 테스트 7개 파일, 정규화 박스 변환, TypeScript 및 Vite 빌드 통과. Vite 메인 청크 500 kB 경고는 남는다.
- Rust 기본 42개, simulation 43개 통과; 각 capability 구성 검사 1개 통과, 합성 성능 시험 1개 제외. 로컬 TCP로 실제 JPEG 패킷 수신과 헤더 크기 초과 거부, 프로토콜·시각·프레임 불일치·좌표·객체 수 검사를 확인했다. 루프백 테스트는 승인된 환경에서 실행했다.
- Tauri 릴리스 및 Ubuntu 24.04 amd64 DEB 성공. DEB `src-tauri/target/release/bundle/deb/FireScene GCS_0.1.0_amd64.deb`: **5,672,358 bytes**, Stage 11의 5,640,630 bytes 대비 **31,728 bytes 증가**. 실행 파일 18,621,248 bytes, frontend/dist 680,496 bytes. DEB 목록에서 개발 서버와 시험 이미지는 발견되지 않았다.
- `tools/camera_perception_fixture.py`는 Pillow가 필요한 개발 전용 합성 영상 생성기다. `--case`로 다중 객체·불일치·오래된 시각·중단·잘못된 입력·과속 송신을 선택할 수 있다. 이 시나리오의 실제 GUI 결과, 3초 타임아웃 및 고속 수신의 장시간 부하, 통신 중 PX4 안전 감시 동시 동작은 아직 자동 또는 GUI로 검증하지 않았다.

## 사용자 확인 및 후속 작업

Ubuntu GUI에서 앱을 실행하고 별도 터미널에서 `python3 tools/camera_perception_fixture.py`를 시작한다. 카메라 화면에 `127.0.0.1`, `8766`을 입력해 TEST ONLY 영상·오버레이·확대와 메뉴 이동 시 정리를 확인한다. 각 `--case`로 오류·OFFLINE 표시와 오래된 영상 제거를 확인한다. 이 단계는 합성 영상만 사용한다. 실제 Raspberry Pi·카메라, 물리적 거리, Windows WebView2, Ubuntu DEB 설치 및 GUI는 **PENDING**이다. 팀과 프로토콜·시계·좌표계를 합의하고 실제 기기로 지연·CPU·메모리·네트워크 사용량을 측정한다. 신뢰 가능한 채널 설계와 Depth 원본 연동은 별도 단계에서 진행한다.
