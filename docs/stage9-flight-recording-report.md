## 저장 구조

사용자 데이터 디렉터리의 `recordings/`에 세션별 JSON Lines (`.jsonl`)를 저장한다. 임무 JSON과 API 키는 별도다. 별도 데이터베이스 서버나 신규 라이브러리는 추가하지 않았다. JSONL은 순차 추가와 불완전한 마지막 줄 복구가 단순하고 설치 부담이 작다. SQLite는 인덱스·시간 범위 탐색 및 대규모 동시 질의에 유리하지만 추가 의존성과 마이그레이션이 필요하다. 현재 JSONL은 조회 시 파일 전체를 다시 읽으므로 긴 기록과 많은 파일에서 SQLite보다 느리다.

버전 1의 첫 줄 `header`에는 기록 ID·이름·시작 시각·임무 ID·연결 세션·출처·기체 식별자를 넣는다. `sample`은 단조 증가 경과 시간, 수신 시각 및 기존 연결·텔레메트리·안전 스냅샷을 포함한다. `connection`은 관측된 연결 단계 변화, `event`는 안전 이벤트의 관측·변경, `end`는 종료 시각을 담는다. 텔레메트리 필드의 원래 메시지 출처, 시스템/컴포넌트 ID, 수신 시각, LIVE/STALE/INVALID를 보존한다. 수신되지 않은 값은 만들지 않는다. 기록 시작 전 발생해 여전히 활성인 경고는 별도로 표시하고 신규 경고 개수에 더하지 않는다. 목록의 경고 수는 기록 중 새로 발생한 WARNING/CRITICAL의 고유 이벤트 수다.

기록 스레드가 기존 상태를 **초당 한 번 샘플링**한다. 모든 MAVLink 프레임을 기록하는 방식이 아니며 1초 사이 변한 값이나 상태 메시지, 빠른 연결 전이는 누락될 수 있다. 경고 발생 시각은 원본 이벤트에도 있지만 재생 점프는 이를 처음 관측한 샘플 시점 단위다. 쓰기는 통신 스레드와 별도이며, 종료 요청은 비동기로 전달한다. 파일은 초당 쓰고 약 5초마다 동기화하며 종료 시 최종 동기화를 시도한다. 실패 시 오류를 표시하고 기록을 멈추며 기존 통신 코드를 중단하지 않는다. 새 연결 세션이 감지되면 세션이 섞이지 않도록 기록을 중지하고 미완료로 표시한다. 정상 앱 종료 시 스레드 종료와 동기화를 시도하지만 실제 GUI 종료·강제 종료 및 전원 손실 시험은 미수행이다.

파일당 50 MiB, 기록 최대 200개, 한 줄 512 KiB로 제한한다. 용량이나 디스크 오류가 발생하면 중지하고 오류를 표시한다. 자동 삭제는 없으므로 사용자가 기록을 정리해야 하며 최대 총량은 약 9.77 GiB에 달할 수 있다. 종료 줄이 없거나 마지막 줄이 불완전하면 완전한 앞부분만 읽고 미완료로 표시한다. 중간의 완전한 잘못된 줄은 손상으로 표시하고 원본을 보존하며 원본 내보내기 또는 확인 후 삭제를 제공한다. 기록 이름은 별도 `.name` 파일이므로 내보낸 JSONL 헤더에는 원래 이름이 남는다. JSONL 내보내기는 사용자 데이터의 `recording-exports/`에 저장하고 경로를 표시한다.

## 재생과 실시간 분리

비행 기록 메뉴에서 이름·임무 연결·시작/종료/크기·목록 검색·이름 변경·삭제 확인·JSONL 내보내기를 제공한다. 재생은 자체 React 상태와 전용 OpenLayers 레이어를 사용하며 Stage 5 실시간 텔레메트리 저장소나 Stage 6 안전 감시에 재생 데이터를 쓰지 않는다. 화면은 REPLAY와 과거 경고를 명시하고, 상단에는 현재 LIVE/OFFLINE/SIMULATION 상태와 실제 안전 배너를 유지한다. 재생은 비행 시작·ARM 또는 드론 명령을 의미하지 않는다.

재생/일시정지, 처음, 위치 이동, 0.5·1·2·4배 및 관측된 연결/안전 이벤트 시점 이동을 구현했다. 최신 샘플은 최대 2.5초 동안 기록된 과거 값으로 유지하며 그 이후·연결 손실·무효 상태는 비운다. 값 보간은 하지 않는다. 배터리·상대/해발 고도·속도·상승률·자세·방향·ARM·모드·GPS·상태 메시지와 인공수평계를 표시한다. 그래프는 현재 10분의 관측 점만 사용하고 결측 및 2.5초 초과 간격을 이어 그리지 않으며 연결 상태와 이벤트를 별도 표시한다. GPS 지도는 유효한 동일 송신자의 원시 좌표만 사용하고 현재 10분 범위의 마지막 500개 샘플까지 표시한다. 지도 네트워크 오류는 재생·실시간 안전 감시와 별도다.

파일 조회는 블로킹 작업 스레드에서 수행하고 10분 구간, 최대 1600개 레코드 및 이벤트 목록 최대 1000개로 제한한다. 화면 데이터는 자동 다운샘플링 대신 해당 구간을 제한해 렌더링한다. 1600개를 넘는 구간은 일부가 표시되지 않고 화면에 제한을 표시한다. 이벤트 1000개 이후는 목록에서 접근할 수 없지만 원본 JSONL에 남는다. 임의 위치 조회는 현재 파일 전체를 다시 순차 읽으며, 200개 대형 파일 목록 검색도 I/O가 클 수 있다. UI는 구간 전환 요청을 짧게 지연하고 이전 응답이 새 구간을 덮지 않도록 한다. CPU·RAM·디스크 처리량은 실제 대상 장비에서 측정하지 않았다.

## 검증

- Rust 기본 단위 테스트 32개와 capability 구성 테스트 1개 통과. 합성 데이터로 기록 스레드 시작·중지·최종화, 연결 변화, 기존 경고 표시, JSONL 시간 순서·부분 끝줄, 손상·경로 검증, 50 MiB 제한, `/dev/full` 쓰기 오류, 원본 내보내기와 삭제를 시험했다. 실제 앱을 재시작한 GUI 시험은 아니다.
- 개발 전용 루프백 UDP 테스트에서 디코딩한 텔레메트리가 기록 스냅샷에 반영됨을 확인했다. 샌드박스의 UDP 차단으로 기본 실행은 실패했고 권한을 받은 루프백 실행은 통과했다. 실제 드론의 전체 기록·재생 시험은 PENDING이다.
- 프론트엔드 테스트 5개 파일 및 TypeScript 검사·빌드 통과. 속도별 진행, 시간 이동·미수신/연결 끊김 처리, 유효 GPS의 송신자·최신성 구분 및 기존 Stage 3~8 오프라인 테스트를 포함한다. GUI 조작·지도 타일·실제 안전 경고와 동시 재생은 검증하지 않았다.
- 합성 UDP 스냅샷 하나는 2,909 bytes였고 별도의 두 샘플 JSONL 시험 파일은 1,233 bytes였다. 전자는 일부 필드만 있는 스냅샷이고 후자는 매우 작은 합성 예제다. 예를 들어 약 3 kB/초라면 약 10 MiB/시간이지만 이벤트·필드 수와 실제 트래픽에 따라 달라지므로 실측치가 아니다.
- Ubuntu Tauri 릴리스 DEB 빌드 성공. 최종 파일은 5,602,686 bytes(5.34 MiB)로 Stage 8의 5,478,140 bytes(5.22 MiB)보다 124,546 bytes 증가했다. Vite 500 kB 청크 경고가 남는다. 프로덕션 기본 빌드는 `simulation` 및 3D 실험 feature를 켜지 않는다.

```sh
cd /home/jiwon/autonomous-uav-system
```

기체가 준비되지 않았다면 실제 기체 시험은 보류한다. 추후 적절한 개발용 시뮬레이션 또는 안전한 읽기 전용 연결에서 비행 기록 메뉴의 시작·종료, 임무 선택, 연결 손실, 화면 이동 중 기록 상태 및 종료 후 재시작을 확인한다. 저장된 기록에서 재생 속도·위치 이동·지도 경로·이벤트 이동·내보내기·삭제 확인을 시험하고, 재생 중 상단 실시간 안전 경고가 과거 값으로 바뀌지 않는지 확인한다. 양 테마 및 창 크기, 디스크 가득 참·강제 종료 후 복구는 별도의 시험 데이터로 확인한다. 실제 기체 명령, 영상 녹화, 점군 저장 및 3D 기능은 추가하지 않았다.
