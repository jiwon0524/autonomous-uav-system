# Stage 4 — 자동 장치 감지 및 시뮬레이션 기반

## 범위

Stage 3 `586084f`와 디자인 태그 `design-v1.0`을 기준으로 자동 탐색 및 수신 전용 테스트 경계를 추가했다. 실제 FC, 무선 텔레메트리, 프로펠러 및 기체는 연결·작동하지 않았다. 실제 장비 검증은 [체크리스트](hardware-validation-checklist.md)에서 모두 PENDING이다. 기존 디자인과 9개 메뉴 및 명령 잠금은 유지한다.

## 자동 연결

앱이 실행 중이면 React 연결 관리기가 약 2초 간격으로 USB 직렬 포트와 상태를 조회한다. USB 장치 추가·제거는 다음 조회 시 목록에 반영된다. 전체 장치를 열어 탐색하지 않는다. 포트 감지는 기체 확인이 아니다. 사용자는 수동으로 포트를 선택하거나, **선택 장치 자동 연결 허용**을 명시적으로 누를 수 있다. 자동 연결은 VID·PID·비어 있지 않은 USB 일련번호가 모두 일치하고 후보가 하나뿐인 경우에만 시도한다. 백엔드도 같은 허용 정보와 현재 열거 결과를 다시 검사한다. 일련번호가 없거나 중복되면 자동 연결하지 않는다. 식별자는 위조되거나 재사용될 수 있으며 장치 인증이 아니다. 열거와 열기 사이 장치가 바뀌는 경쟁 가능성도 완전히 제거되지 않았다.

허용 장치 및 마지막 선택은 WebView 로컬 저장소에 보관하며, 앱 재시작 시 허용 설정을 복원한다. 저장소를 지우거나 사용할 수 없으면 유지되지 않는다. 마지막 선택은 성공한 기체 연결을 의미하지 않는다. 수동 연결과 시뮬레이션 시작은 자동 연결을 끈다. 사용자의 연결 해제는 허용 설정을 지우고 대기 중 자동 연결을 중지한다. 동일 시점에 한 연결만 허용한다. 허용 장치가 없으면 다시 나타나기를 기다리고, 실제 열기 시도는 한 앱 실행에서 최대 3회이며 시도 사이 최소 5·10초 간격을 둔다. 이후 다시 활성화해야 한다. 연결 중단 시 현재 기체 값은 지우고 이전 HEARTBEAT 시각만 구분해 남긴다. 기존 10초 대기 및 5초 손실 기준은 실측값이 아니다.

접근 및 포트 점유 오류는 연결 오류로 표시한다. Linux `flock`/`TIOCEXCL`은 이미 포트를 연 모든 비협력 프로세스를 식별한다고 보장하지 않으므로 QGroundControl 등은 종료해야 한다. 연결 대상의 물리적 진위 및 실제/가상 출처는 자동으로 입증할 수 없다.

## 출처 및 시뮬레이션

상태는 OFFLINE, HARDWARE LINK, SIMULATION 및 출처 미검증을 표시한다. HARDWARE LINK는 사용자가 선택·허용한 USB 전송 경로라는 뜻이며 실제 기체라는 인증이 아니다. SIMULATION은 사용자가 시작한 모드라는 뜻이며 송신자 신원은 미검증이다. 연결 손실 시 OFFLINE과 마지막 경로를 함께 표시한다. 어느 모드에서도 CRC와 HEARTBEAT는 인증이 아니다.

시뮬레이션 버튼은 `127.0.0.1:14540`에 수신 전용 UDP 소켓을 열어 기존 MAVLink 검사와 동일한 상태 기계를 사용한다. 외부 인터페이스를 바인딩하지 않으며 수신 외 소켓 송신 API는 노출하지 않는다. 이미 점유된 포트는 오류다. 이는 로컬 데이터의 사용자 지정 시뮬레이션 경계이며 모든 로컬 송신자가 시뮬레이터라고 보장하지 않는다. [PX4 1.16 공식 문서](https://docs.px4.io/v1.16/en/simulation/)는 오프보드 API 수신 포트 14540과 GCS 포트 14550을 설명한다. PX4 SITL 자체는 이번에 실행하지 않아 실제 SITL 연동은 미검증이다. 유효한 PX4 형식 시험 메시지와 pseudo-terminal 테스트는 테스트 코드에서만 생성한다. Gazebo·PX4·Python 등은 설치 앱의 필수 의존성이 아니다.

## Windows 및 안전

Windows COM 열거는 기존 `serialport` 추상화를 사용하지만 실제 COM 읽기 전용 transport는 아직 구현되지 않았고 명시적으로 지원 불가 오류를 반환한다. [Microsoft 문서](https://learn.microsoft.com/en-us/windows/win32/devio/communications-resource-handles)는 COM 핸들의 독점 열기 규칙을 설명한다. 읽기 전용 접근·속도 설정·타임아웃을 Windows 및 실제 드라이버에서 검증하기 전 쓰기 가능한 대체 경로를 사용하지 않는다. Windows 빌드와 실행은 미검증이다.

Linux 직렬 핸들은 `O_RDONLY`를 유지한다. 프로덕션 코드에 기체 명령이나 MAVLink 송신 경로는 없다. 시험 코드의 UDP 전송은 loopback 시험 메시지 생성 전용이다. 인증되지 않은 메시지 및 현재 시뮬레이션 모드는 실기체 식별·비행 승인에 사용할 수 없다.

## 검증 결과

- Rust 테스트 9개 통과: 허용되지 않은 자동 연결 차단, 모의 loopback 시뮬레이션 수신 및 중복 세션 차단, 기존 가상 직렬 유효·오류 프레임, 포트 독점·OS 쓰기 차단, 해제, 시간 초과 및 수신 중단. loopback 시험은 샌드박스의 `Operation not permitted` 때문에 샌드박스 밖에서 수행했다.
- 프론트엔드 정적 테스트: 9개 메뉴·명령 잠금, 시뮬레이션 출처/연결 손실 표시 및 가상 장치 추가·제거·다른 식별자·중복 후보와 재시도 한도 검증. 가상 장치 데이터는 실제 하드웨어가 아니다. 장치 감지→허용→실제 포트 재연결의 전체 GUI 경로와 실제 USB 권한·점유 상태는 미검증이다.
- TypeScript 검사, 프론트엔드 빌드, 프론트엔드 정적 테스트 3개 및 `cargo tauri build --no-bundle -- --offline` 릴리스 빌드가 통과했다. 실제 Tauri GUI, PX4 SITL 및 설치 패키지 실행은 이번에 검증하지 않았다.

## Stage 5 후보

실제 장비 준비와 별개로 SITL의 실제 실행·포트 설정 및 GUI 통합 테스트를 수행하고, Windows 수신 전용 COM transport의 구현·검증, USB 재연결 통합 테스트와 데이터 출처 표시를 개선한다. 통신 데이터의 freshness와 실제/시뮬레이션 출처를 인증할 수 있는 방식은 별도로 설계한다. 비행 명령은 별도 승인 전까지 구현하지 않는다. 변경 파일 및 로컬 커밋은 `git log -1 --stat`으로 확인한다. 원격 push는 하지 않는다.
