# Stage 11 Companion Computer 연동 기반 보고

기준: `dev/firescene-gcs`, Stage 10 `2f0bec5`, 디자인 `design-v1.0`. 이 단계의 로컬 커밋은 이 파일을 포함한 `git log -1`로 확인한다. 원격 push는 하지 않았다. 실기체 운용 검증이나 자율비행 구현이 아니다.

## 설계와 구현

상태용 TCP JSON Lines를 선택했다. GCS가 사용자 지정 숫자 IP·포트로만 나가는 클라이언트이며 수신 포트나 네트워크 탐색을 추가하지 않는다. TCP·UDP·WebSocket·HTTP·ROS2의 비교와 영상/점군 별도 채널의 이유는 [인터페이스 규격](companion-interface-spec.md)에 정리했다. ROS2 설치는 필수가 아니다.

독립 Rust manager는 최대 4096바이트 메시지, 스키마 v1·값·시각 검사, 3초 접속 제한, 5초 유효 메시지 무수신 감지, 초기 연결 후 최대 3회 재접속 및 사용자 해제를 지원한다. 한 개의 최신 스냅샷만 유지하며 PX4 연결 및 안전 감시를 참조하거나 수정하지 않는다. 연결 손실 때 기존 수신 값을 현재 값으로 표시하지 않는다. 설정 주소는 세션에만 존재하며 앱 재시작 후 다시 입력해야 한다. 연결은 자동 실행하지 않는다.

시스템 설정에서 IP·포트 및 상태를 표시하고 기존 자율비행·카메라·3D 매핑 화면에서 Companion/AI/카메라/매핑 및 마지막 수신 상태를 표시한다. 관련 실제 기능은 개발 예정이다. 상태·식별자는 상대방의 인증되지 않은 주장이다. 개발용 루프백 시험 도구는 `tools/companion_status_fixture.py`이며 DEB에 없다. 카메라 및 3D 입력·출력의 합의할 메타데이터는 규격에 정의했다. 실제 전송 형식이나 팀원 구현과의 호환성은 아직 확정하지 않았다.

## 보안과 한계

평문 TCP에는 인증·기밀성·무결성·재생 방지가 없으므로 신뢰 가능한 격리 시험망에서만 사용한다. 장치 ID는 인증이 아니며 시각 검사는 재생 방지가 아니다. 운영 전 상호 인증, 키 관리, 권한·장애 모델을 설계해야 한다. 외부 장치가 허위 상태를 보낼 수 있고 높은 전송률에 대한 부하 제한 및 DoS 내성은 검증하지 않았다. 동시 작업은 기존 FC 수신 경로와 분리되며 Companion에는 송신 명령, 셸, 비행 제어가 없다. 상태 정보는 안전 판정에 사용하지 않는다.

## 검증 및 배포

- 프론트엔드 테스트 6개 파일 통과, TypeScript 검사 및 Vite 프로덕션 빌드 통과. 500 kB 초과 메인 청크 경고는 남는다.
- Rust 기본 38개 및 simulation 39개 통과, 각 capability 구성 검사 1개 통과, 각 합성 성능 시험 1개 제외. 로컬 TCP 연결·수신·상대 종료 및 손실, 유효/무효 스키마·크기·시각·주소, 미수신 상태를 테스트했다. 루프백 및 simulation 테스트는 승인된 샌드박스 밖 환경에서 실행했다. 5초 정지 타임아웃과 재시도 소진, GUI 조작 및 실제 FC 동시 동작은 별도 통합 검증이 필요하다.
- Tauri 릴리스·Ubuntu 24.04 amd64 DEB 생성 성공. 패키지 목록에서 개발 시험 도구는 발견되지 않았다. 설치 및 GUI 실행은 미검증이다.
- DEB: `src-tauri/target/release/bundle/deb/FireScene GCS_0.1.0_amd64.deb`, 5,640,630 bytes. Stage 10의 5,622,548 bytes 대비 18,082 bytes 증가. 실행 파일 18,527,912 bytes; 프론트엔드 dist 674,713 bytes (`du -sb`).
- GUI/Pi 5 연결, 실기체·KOA FC·센서, 장시간·악성 송신 부하, Windows 전체 빌드·설치·장치 시험은 **PENDING**. 현장 failsafe 및 안전 임계값도 실기체 검증 전이다.
