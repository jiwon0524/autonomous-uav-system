# Stage 19.5 사용성 및 하드웨어 사전 검증

기준: dev/firescene-gcs, 1b22aa5. Stage 0 미추적 보고서와 기존 데이터는 유지했다.

## 변경

- 시스템 설정에 QGroundControl AppImage 탐색, 사용자 지정 절대 경로와 명시적 실행 버튼을 추가했다. 셸은 사용하지 않으며 QGroundControl 이름의 파일만 실행한다. 위치와 실행 오류를 표시하고 직접 USB, QGC 및 Router 전달과 포트 충돌을 안내한다. 홈의 GroundControl.AppImage를 찾았으나 실행 비트가 없어 사용자가 권한을 확인해야 한다.
- 텔레메트리와 분리된 오프라인 키 입력 연습을 추가했다. 연결 미리보기와 같은 키와 타임아웃을 사용하고 비행 명령은 전송하지 않는다. 포커스 및 화면 숨김에서 종료한다.
- 직렬 장치 없음, 권한 부족, 포트 점유 및 UDP 점유 오류를 구분한다. 기존 HEARTBEAT 대기 시간 초과 및 손실 표시는 유지한다. 운영체제가 제공하는 오류에 따라 포트 점유를 일반 오류로 표시할 수 있다.

## 검증

- 프런트엔드 테스트 12개 파일 통과; TypeScript 검사 및 프런트엔드 빌드 통과.
- Rust 기본 47개, simulation 48개 통과, 각각 벤치마크 1개 무시. Tauri 명령 권한 통합 테스트 통과. 샌드박스에서 로컬 소켓이 거부되어 권한을 받아 재실행했다.
- 기존 자동 시험은 수신, HEARTBEAT 손실, 배터리/GPS 경고, 오래된 데이터, 기록 및 재생, 입력 상태 등을 개별적으로 다룬다. telemetry_feed를 이용한 전체 GUI 종단 간 시나리오는 실행하지 못했다.
- 코드 검토상 직렬 파일은 읽기 전용이며 비행 명령 송신 경로가 없다. simulation 수신 명령과 생성기는 feature 조건으로 제한되고 기본 빌드에 포함되지 않는다. Tauri 셸 범용 권한은 추가하지 않았다.
- 이 환경의 DISPLAY=:1은 X 서버에 접근할 수 없어 실제 GUI를 검증하지 못했다. 9개 메뉴, 두 테마, 창 최대화/복원, 지도와 위성, 검색/건물/범위, 임무 저장 및 재시작 복구, 키 연습, 연결/오류, 기록 목록/재생은 Ubuntu 데스크톱에서 직접 확인해야 한다. 실제 VWorld 네트워크 연동과 실제 드론도 미검증이다. 3D는 기본 비활성이다.
- 키 입력 단위 시험은 해제, 상반 입력, Space, Escape에 해당하는 종료, 포커스/숨김/메뉴/종료 상태 전이, 연결 및 최신성 손실과 시간 초과를 다룬다. 실제 창 이벤트와 최소화는 GUI에서 확인해야 한다. 초기화는 기체 정지나 위치 유지를 보장하지 않는다.

## 배포와 남은 작업

패키지 이름과 아이콘, 의존성 및 desktop 등록은 DEB 메타데이터로 확인한다. 설정은 Tauri 앱 설정 디렉터리, 임무와 기록은 앱 데이터 디렉터리 및 웹뷰 로컬 저장소를 사용한다. 기존 경로는 변경하지 않았다. 설치/업데이트 및 종료 처리의 실제 데스크톱 검증은 남아 있다. Windows 빌드와 설치도 별도 환경에서 확인한다. 내일 순서는 [하드웨어 가이드](stage16-hardware-test-guide.md)를 따른다. 실제 비행 및 모터 제어는 범위 밖이다.

Ubuntu DEB: `src-tauri/target/release/bundle/deb/FireScene GCS_0.1.0_amd64.deb`, 5,713,738 bytes. 이전 5,710,474 bytes 대비 3,264 bytes 증가. DEB에서 FireScene GCS desktop 항목, 아이콘, 실행 파일 및 런타임 의존성을 확인했다. 실제 설치는 미검증이다. 빌드 산출물의 VWorld 환경변수 키 패턴 검색에서는 일치 항목이 없었다. 이는 모든 가능한 비밀의 부재를 증명하지 않는다. 로컬 커밋은 이 보고서를 포함하는 커밋이며 `git log -1`로 확인한다.
